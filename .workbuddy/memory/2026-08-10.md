## LLM 403/401 额度排查（18:11）
- 用户报 qwen-plus 403 `AllocationQuota.FreeTierOnly`（免费额度耗尽+仅免费额度开关）。
- 核验结果：
  - 源码 `.env` 的 Key（`...XEYMY...`）实测 HTTP 200，qwen-plus 正常返回 → 该 Key 当前可用，原 403 是控制台额度状态（现已恢复），非代码问题。
  - `dist\Assistant\.env` 的 Key（`...LIRRP...`）实测 **HTTP 401 invalid_api_key，已失效** → 这是打包 exe 真正报错的根因（用户把"源码好 Key"和"exe 坏 Key"混淆）。
- 已修复：把 `dist\Assistant\.env` 的 `QWEN_API_KEY` 与 `DASHSCOPE_API_KEY` 统一替换为可用的 `XEYMY` Key，重新验证 HTTP 200。
- 经验：运行 exe 报错时优先核对 `dist\Assistant\.env` 的 Key 是否与源码 `.env` 一致、是否仍有效。

## LLM 403 真凶：Windows 环境变量污染（18:53）
- 用户启动 `启动语音助手.bat`（源码模式）仍报 403 `FreeTierOnly`，但 curl 测 `XEYMY`（源码/同级 .env 的 Key）明明 HTTP 200。
- **真正根因**：Windows **用户级环境变量** `QWEN_API_KEY` 被设成了第三把 Key `...RELYHDP...`（仅免费额度+额度耗尽 → 403，与用户报错文字完全一致）。`python-dotenv` 默认 `override=False`，已存在的系统环境变量会盖掉 `.env` 文件，所以 app 一直用 RELYHDP 请求。
- 三处修复：
  1. `src/main.py` 的 `load_dotenv(env_path, override=False)` → **`override=True`**（让 .env 始终优先；源码+exe 都受益，防止此类污染再发生）。
  2. 清掉失效的 Windows 用户环境变量 `QWEN_API_KEY`（PowerShell `[Environment]::SetEnvironmentVariable('QWEN_API_KEY',$null,'User')`）。
  3. `dist\Assistant\_internal\.env`（打包资源模板）的死 Key `...LIRRP...`（401）也换成 `XEYMY`，保证换机器/缺同级 .env 时 exe 仍能用正确 Key。
- 验证：模拟"环境变量被污染"场景，load_dotenv(override=True) 后 `QWEN_API_KEY` 正确解析为 XEYMY。
- **关键经验**：app 报 LLM 403/额度类错误时，务必检查（a）实际生效的 Key 是不是 `.env` 里的那把（查 Windows 用户/机器环境变量），（b）`load_dotenv` 是否 override。环境变量污染会比 .env 配置优先级更高。

## 新增：LLM 回复清理模块（clean_response）

**用户反馈**：LLM 回复含大量 Markdown 格式噪音（`**`、`✅`⚠️` Emoji、`→` 箭头、`[工具名]` 引用），TTS 会把这些符号逐字念出来（如"星号""对勾"），用户体验差。

**改动（两层治理）**：

### 1. 源头：系统提示词禁止格式化（`agent_service.py`）
- 旧提示词明确要求 LLM 用 `📝 📎 🔗 ⚠️` 等 Emoji 分点 → **已删除**
- 新增「回答风格与输出格式」章节：
  - 明确禁止 Markdown 粗体/斜体/Emoji/箭头/方括号工具引用/代码块
  - 要求用中文数字「第一」「第二」或「1.」「2.」分点
  - 给出正确/错误对比示例
  - 强调回复会被 TTS 播报，必须是可"念出来"的干净文本

### 2. 兜底：回复后处理清理函数（`ui_bridge_service.py`）
- 新增 `clean_response(raw, for_tts=False)` 函数（12 个预编译正则）：
  - 清除：`**bold**` `*italic*` `__underline__` `# heading` `` `code` `` `[tool_ref]`
  - 清除：全部 Unicode Emoji 范围（Dingbats + Emoji + Misc Symbols）
  - 清除：箭头符号（TTS 模式变逗号，UI 模式保留→）
  - 清除：孤立不配对的 Markdown 标记
  - 标准化：列表标记、多余空白、连续换行
- **双模式输出**：
  - UI 展示版（`for_tts=False`）：去格式但保留→箭头和工具名（可读性好）
  - TTS 播报版（`for_tts=True`）：深度清理，删工具名、箭头变逗号（纯口语）
- 接入点：`_on_agent_final()` 在 emit 气泡和送 TTS 前分别调用

### 验证结果
用截图实际文本测试，7 类噪音全部清除（`**` `*` ✅ ⚠️ → [工具名] \`），TTS 输出为干净自然语言。
